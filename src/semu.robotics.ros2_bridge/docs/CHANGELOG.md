# Changelog

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [1.1.0-isaac5.1-jazzy] - 2026-10-12 (branch isaac5.1-jazzy)
### Changed
- Branch for ROS 2 Jazzy: `bin/`, `packages/` and `exts/` are built against the Jazzy
  `control_msgs` with Isaac Sim 5.1's bundled Jazzy rclpy (Python 3.11).
  `tools/build.sh [humble|jazzy]` selects the distro; `packages/ROS_DISTRO` records
  which one the committed artifacts are for. `extension.toml` is unchanged (Isaac 5.1
  bundles both distros under `isaacsim.ros2.bridge`).

## [1.0.1-isaac5.1] - 2026-10-12
### Fixed
- `JointTrajectoryControllerState` publishing on ROS 2 Jazzy: control_msgs >= 4.6
  removed the legacy `actual` / `desired` fields, which raised an
  AttributeError every physics step. They are now written only when present;
  `feedback` / `reference` / `error` / `output` are always filled.

## [1.0.0-isaac5.1] - 2026-10-11 (fork: ry0hei-kobayashi, branch isaac5.1-humble)
### Changed
- Rebuilt for Isaac Sim 5.1 / Python 3.11 / ROS 2 Humble: `bin/`, `packages/`
  (`control_msgs`, `add_on_msgs`), the Cython-compiled `_ros2_bridge` module and the
  packaged `exts/` tree are regenerated by `tools/build.sh` (Docker). The extension
  config targets `cp311`, depends on `isaacsim.ros2.bridge` instead of
  `omni.isaac.ros2_bridge` and no longer requires `semu.usd.schemas` /
  `semu.robotics.ros_bridge_ui`.
- `Ros2Bridge` creates its components from the extension setting
  `/exts/semu.robotics.ros2_bridge/components` (JSON) when the timeline plays,
  instead of discovering `semu.usd.schemas` prims on the stage.
- `RosAttribute`, `RosControlFollowJointTrajectory` and `RosControllerGripperCommand`
  are constructed with `(node, dci)` and started with explicit service/action names,
  so they can also be used from a host script without the extension.
- `physics_step()` / `update_step()` merged into `step(dt)`.
- `get_stage_units` imported from `isaacsim.core.utils.stage`.
### Added
- `src/add_on_msgs`: source of the service definitions (reconstructed from the
  upstream README and generated code; upstream only shipped generated files).
- Topic interface `/<controller>/joint_trajectory` (mirrors ros2_control's
  JointTrajectoryController); messages are validated on the executor thread and
  installed on the main thread in `step()`.
- `/<controller>/state` and `/<controller>/controller_state`
  (`JointTrajectoryControllerState`) publishers; `controlled_joints` to restrict
  the reported joints.
- Zero `time_from_start` padding (`_zero_time_pad_sec`) so single-point
  trajectories get time to converge; preemption of the in-flight goal when a new
  goal arrives.
- `tools/build.sh`, `tools/Dockerfile.msgbuild`, `tools/build_msgs.sh`.
### Fixed
- `RosControlFollowJointTrajectory._init_articulation` referenced an undefined
  name (`path`) in its "is not an articulation" warning (NameError at runtime;
  caught by the Cython compile).
### Removed
- Python 3.7 / Foxy binaries from upstream (replaced by the rebuilt ones).
